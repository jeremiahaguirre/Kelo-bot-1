# Kelo-bot-1 handoff

## Current goal
Kelo-1 is an autonomous robot who lives in a 3D low-poly Kelowna valley (static GitHub Pages site plus a Windows Electron app).
He must **discover** how his world works by himself. That covers:
- needs
- seasons
- tools
- vehicles

Everything he gets (tools, vehicles, seeds, materials) arrives **only** through his own requests at the Post Office, which the visitor gifts.
He may change the world freely. He can never move or change the buildings, and he can't build new ones.

  - Fixed step (scene.js): `keloSimAdvance(t)` at the top of `animateDiorama` runs whole `KELO_SIM_H` (1/60 s) steps from an accumulator (at most `KELO_SIM_MAX_STEPS` 10 a frame): `keloWalkStep` (A* steering, `keloLocomote`, ice edge, stumbles) and every `keloEveryStep(fn(h, simT))` hook (planned plane flights: `planeFlightsStep` → `planeFlightAdvance`, assembly.js).   - Collision is swept: `keloLocomote` moves in pieces of at most `KELO_SUBSTEP` (0.12), each checked against `worldObstacles` (slide + `pushOutOfObstacles`), so a fast vehicle can't jump a thin wall. `keloMotion.simStep` replaces the old "moved last frame" test.
  - Scripted motion: don't step things on `setTimeout`/`setInterval`. Use `await keloNextFrame()` in a clock-timed loop, or `keloTween(ms, (k, dt) => ...)` (scene.js); both fall back to a slow timer in a hidden tab. Per-frame code uses real `dt` in seconds; easing is `1 - Math.exp(-k * dt)` (a 60 fps factor f is k = -ln(1 - f) * 60), never a fixed lerp factor or a constant added per frame. `shatterAt` (materials.js) is fixed-step physics (30 ms steps, floor clamp in each, drawn interpolated).
  - Chunks (`js/chunks.js`, after perf.js): every static object is registered into a 32-unit chunk (`CHUNK_SIZE`; the grid is a sparse map with no bounds, so a bigger world just adds chunks). Nothing is reparented: each registered mesh gets a `KeloChunkLayers` (its `test()` is what the renderer asks first), so `.visible` stays yours. Each frame a chunk is drawn if its box is in view (plus a margin) and within `graphics().drawDist` (High 900, Balanced 600, Fast 440) or the fog's 1% distance, whichever is nearer; it casts shadows only if its box is in the sun's shadow box. Chunks more than 24 units away and quiet for 4 s are drawn as one merged mesh per material (same materials and triangles; swaying trees keep their own phase through a `keloRoot` attribute); any change (move, turn, scale, hide, material, geometry, shadow flag) is caught by a rolling check and the chunk shows its real meshes again at once; the changed mesh stays out of merges for 15 s. Small shadow casters (realism.js `smallCasters`) never cast from a merge. Registration rescans every 2 s (new things join; anything that moves off its spot is let go and culled by three.js as before). Never registered: Kelo-1, vehicles, assembly builds, wildlife, companions, carried objects, clouds, birds, sky, points/lines/sprites. Debug: `window.KELO_CHUNKS_OFF = true`, `chunkStats()`.

## Architecture decisions
- **No build step.** The page uses plain global-script JS loaded in order from `index.html`:
  twtheme (right after the Tailwind CDN script) → three.js r128 + OrbitControls (CDN) → js/vendor (GLTFLoader, RGBELoader, Sky, CopyShader, LuminosityHighPassShader, EffectComposer, RenderPass, ShaderPass, UnrealBloomPass) →
  braincharter → agent → roads → loopguard → agenda → memory → worldclock → needs → forms → netnode → conversation → postoffice → workshop → hobbies → mining → growth → kelo-body → scene → realism → weldstudio → house → animations → kelo-mocap-data → kelo-mocap → kelo-clips → motion → humanize → kelo-ik → kelo-handoff → items3d → gearmodels → everydaymodels → materials → itemmodels → realmodels → perf → chunks → storehouse → museum → basements → interiors → viewer → takeout → tidyup → vehicles → landfill → disposal → knowhow → itemuse → seasons → wind → weather → landscape → groundwork → welding → workbench → plantcare → skills → trips → projects → bom → buildmodels → assembly → town → coderequests → wishfeatures → wildlife → companions → pastimes → paintrender → paintstudio → shopkeeping → printer → machinemodels → workshopbuilding → machines → additive → cnc → electronics → garage → glassstudio → woodshop → forklift → shopmaker → upgrades → main → portal → talk → explore → eyecam → shopvisit → minimap → tryit → plants → plantmodels → workshopnorth → roadworks → agendalinks → hud → menuui
  (This is the order in index.html as of 2026-11-12; index.html is the source of truth. `js/native.js` is injected before agent.js only in the phone build by scripts/build-web.mjs.)
  (`js/shop.js` is loaded only by `shop.html`.) A later file silently replaces a same-named function from an earlier one, so keep top-level names unique.
  Three.js r128, Tailwind and Phosphor all load from CDN; three.js add-ons are vendored in `js/vendor` and assets live in `assets/` (served from 'self'). Other languages are allowed if they help.
- **State and persistence.**
  - One global `state` object.
  - `keloStore` wraps localStorage on the web and a 10 GB disk store in Electron (`desktop/`).
  - Autosave runs every 20s, on visibility change and on pagehide.
  - New fields persist automatically unless they are listed in `TRANSIENT_STATE_KEYS`.
- **Thinking.** The AI order is Gemini, then Claude, then a built-in brain. Keys live only on the device. **Never commit API keys.**
- **Movement.**
  - A* pathfinding avoids `worldObstacles` circles.
  - `ridingSpeed` scales the walk step.
  - Paths over water and through the air are straight lines.
- **Vehicles.**
  - `VEHICLE_TYPES` covers truck, excavator, boat, bike, snowmobile and air.
  - Vehicles park in `YARD_SLOTS` or `DOCK_SLOTS` and are excluded from the storehouse shelves.
  - The Disposal Pit (which replaced the spoil heap) is at (20, -9).
- **Phone apps (Capacitor 8).** `npm run cap:sync` builds `www/` (git-ignored) with `scripts/build-web.mjs`: local three/Phosphor/fonts, compiled Tailwind, an app-only CSP, and `js/native.js` + `css/native.css` injected before agent.js. `native.js` exposes `window.keloNative` (memory files loaded into a cache before any DOMContentLoaded handler runs, write-through saves; Keychain/Keystore keys with the same getKeys/setKeys shape as `keloDesktop`). Native projects in `android/` and `ios/`; CI in `mobile.yml`; owner guide in `docs/MOBILE.md`. If you add a CDN script to index.html, add its local copy to build-web.mjs (the build fails loudly otherwise).
- **Cloud dreams.** `.github/workflows/dream.yml` runs every 6h and writes `brain/growth.json`. `desktop.yml` builds the Windows app.
